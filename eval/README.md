# Оценка распознавания скриншотов

Проверяет, насколько точно ИИ находит строки с треками на скриншотах (PLAN.md, этап 3.7).
Цель FR-6: не меньше 90 % строк распознано правильно (recall ≥ 0.90).

## 1. Соберите скриншоты

Положите 30–50 скриншотов в `eval/screenshots/` (папка не попадает в git). Нужна смесь:

- приложения: Яндекс Музыка, VK Музыка, Spotify, Shazam, по возможности Apple Music, YouTube Music, Telegram;
- страницы: плейлист, альбом, история, «Сейчас играет», поиск, чарт;
- светлая и тёмная тема;
- длинные скриншоты (прокрутка) и строки с обрезанными названиями («…»);
- пара «трудных» случаев: блок «Похожие» или рекомендации под списком, реклама, мини-плеер с другим треком.

Имена файлов любые, без пробелов удобнее: `yandex_playlist_dark_01.png`.

## 2. Запишите ожидаемый ответ

Скопируйте `expected.example.json` в `expected.json` и для каждого файла перечислите строки основного списка
сверху вниз — так, как они **должны** быть распознаны:

```json
{
  "yandex_playlist_dark_01.png": {
    "source_app": "yandex_music",
    "items": [{"artist": "КИНО", "title": "Группа крови"}]
  }
}
```

- `source_app`: `yandex_music`, `vk`, `spotify`, `shazam`, `apple_music`, `telegram`, `youtube` или `other`.
- Обрезанное на экране название пишите **полностью** — так проверяется дедупликация и угадывание.
- Строки из «Похожих», рекламы и мини-плеера **не** включайте.

## 3. Запустите

В `.env` должен быть задан `LLM_API_KEY` (или локальный `LLM_BASE_URL` для Ollama). Затем:

```bash
cd hub && uv run python ../eval/run_eval.py
```

Опции: `--only file1.png file2.png` — только эти файлы; `--threshold 0.85` — порог совпадения строки;
`--no-save` — не сохранять подробный отчёт в `eval/results/`.

Скрипт печатает по каждому файлу precision/recall, пропущенные (`-`) и лишние (`+`) строки, затем итог и
стоимость. Строка считается найденной, если нормализованные исполнитель и название похожи на ожидаемые
не меньше чем на 0.85 (rapidfuzz).

## Offline-проверка выбора музыкальной записи

Из корня репозитория: `hub/.venv/bin/python eval/run_music_eval.py`.
Не запускает Hub, не читает пользовательскую историю/настройки, не обращается к сети.
Опции: `--corpus eval/music_matches.json`, `--output /tmp/music-matches.json`.

Фиксированный размеченный набор включает оригинал/ремикс/live, разные именованные ремиксы
и концертные площадки, транслитерацию, одинаковое название у разных исполнителей,
превью и отсутствие длительности. Выполняются настоящие `rank_candidates` и `classify`;
ожидания — идентификаторы подходящих записей и допустимость автоматического выбора, не копия формулы.
Отчёт содержит размер набора, каждый score/verdict, число автоматических решений и ложных
автоматических совпадений, их знаменатель, версию политики и SHA-256 набора.
При ложном автоматическом выборе код выхода 1. Маленький синтетический набор не оценивает
точность на реальном трафике и не доказывает идентичность или полноту аудио.
